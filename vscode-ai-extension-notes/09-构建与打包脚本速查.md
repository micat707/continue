# 构建与打包脚本速查(Continue + VS Code fork)

> [!abstract] 一句话
> 两个仓库**各自独立的构建体系**:**Continue** 是 monorepo(extension 依赖兄弟目录 `core`/`gui`/`packages`,要整体装 + 建软链);**VS Code fork** 用 gulp 编译 `src/vs/**`,靠 `scripts/code.bat` 启动开发版。本页只记"用哪个命令、何时用、在哪个目录跑"。

> [!warning] 都是长时间运行的命令
> `install-dependencies.ps1`、`npm run compile`、`npm run watch`、`code.bat` 都是耗时久或常驻的进程,必须在**自己的终端**里手动跑。`install-dependencies.ps1` 里还有一个 node 版本不匹配时**等你按 Enter** 的交互点,跑前先确认 node 版本。

---

## 0. 两个仓库与目录

| 仓库               | 根目录                                       | 构建体系                                           |
| ------------------ | -------------------------------------------- | -------------------------------------------------- |
| Continue(monorepo) | `d:\soft\Kiro_back\My-Agent-editor\continue` | npm workspaces + esbuild;根 `scripts/` 下有 ps1/sh |
| VS Code fork       | `d:\soft\Kiro_back\My-Agent-editor\vscode`   | gulp;`scripts/` 下有 `code.bat` 等                 |

> [!note] node 版本
> Continue 要求 `node >=20.20.1`(见 `extensions/vscode/package.json`),并对照根 `.nvmrc`。版本不符时 `install-dependencies.ps1` 会警告并等待按键。建议先 `nvm use` 对齐。

## 1. Continue · 首次构建 / 整体重建(推荐入口)

**在 Continue 仓库根目录跑:**

```powershell
cd d:\soft\Kiro_back\My-Agent-editor\continue
Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process
.\scripts\install-dependencies.ps1          # Windows
# mac/linux 对应 ./scripts/install-dependencies.sh


#开发模式启动continue的gui 否则 chat对话框出不来
cd d:\soft\Kiro_back\My-Agent-editor\continue\gui

npm run dev


#热模式
D:\soft\Kiro_back\My-Agent-editor\continue\extensions\vscode> npm run esbuild-watch


#生产模式 直接生成vsix文件
cd d:\soft\Kiro_back\My-Agent-editor\continue
Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process
.\scripts\install-dependencies.ps1
```

> [!info] 这个脚本按依赖顺序做了什么(对应 `.vscode/tasks.json` 的 "Install Dependencies" 任务)
>
> 1. 检查 node 版本(对照 `.nvmrc`)
> 2. 根目录 `npm install`
> 3. `node ./scripts/build-packages.js` —— 构建共享包 `fetch` / `openai-adapters` / `config-yaml`
> 4. `core/`:`npm install` + `npm link`(core 发布为本地软链)
> 5. `gui/`:`npm install` + `npm link @continuedev/core` + **`npm run build`**(打包 React GUI)
> 6. `extensions/vscode/`:`npm install` + `npm link @continuedev/core` + **`npm run prepackage` + `npm run package`**(拷 gui 产物进扩展 + 打 vsix)
> 7. `binary/`、`docs/` 装依赖

**什么时候必须用它:** 首次构建、刚拉代码、依赖变动、改了 `core` 或 `gui`。因为 extension 通过 `npm link` 依赖 `@continuedev/core`,且 `prepackage` 会把 `gui/dist` 拷进扩展——这些跨目录关系只有整体脚本能正确建立。

## 2. Continue · 增量 / 单项命令

**都在 `extensions/vscode/` 目录跑**(`d:\soft\Kiro_back\My-Agent-editor\continue\extensions\vscode`):

| 命令                        | 作用                                                                | 何时用                                    |
| --------------------------- | ------------------------------------------------------------------- | ----------------------------------------- |
| `npm run esbuild`           | 编译扩展 TS(带 sourcemap)→ `out/extension.js`                       | 只改了 `extensions/vscode` 的 TS,快速重编 |
| `npm run esbuild-watch`     | 同上 + watch,改动自动重编                                           | 持续开发扩展 TS                           |
| `npm run tsc:check`         | 仅类型检查(`tsc -p ./ --noEmit`)                                    | 想确认类型不出错、不产物                  |
| `npm run prepackage`        | 清 `out/`、`bin/`,拷 `gui/dist`,下载/拷 sqlite、装 native node 模块 | 打包前准备;改了 gui 后要重新拷产物        |
| `npm run package`           | 打成 `continue.vsix`(含上一步产物)                                  | 要安装/分发 vsix                          |
| `npm run lint` / `lint:fix` | ESLint                                                              | 提交前                                    |

> [!tip] GUI 单独构建
> React GUI 在 `continue/gui`,改了前端要在那里 `npm run build`,再回扩展目录 `npm run prepackage` 把新产物拷进去(或直接重跑 §1 的整体脚本)。

> [!note] prepackage 的目标平台
> `prepackage.js` 会按 `--target` 或环境变量 `CONTINUE_VSCODE_TARGET` / `CONTINUE_BUILD_TARGET` / `VSCODE_TARGET` 选平台,缺省自动探测当前平台(如 `win32-x64`)。跨平台打包时才需要显式指定。

## 3. VS Code fork · 编译

**都在 VS Code fork 根目录跑**(`d:\soft\Kiro_back\My-Agent-editor\vscode`):

| 命令                       | 作用                                                                    | 何时用                                       |
| -------------------------- | ----------------------------------------------------------------------- | -------------------------------------------- |
| `npm run watch`            | 增量编译 + watch(client transpile / client / extensions / copilot 并行) | **开发首选**,改 `src/vs/**` 自动重编         |
| `npm run compile`          | 全量编译一次(`compile-client` = gulp compile + `compile-copilot`)       | 编一次就启动,不常驻                          |
| `npm run build-fast`       | 快速构建(transpile + 扩展 + copilot),比 compile 快                      | 想快点出产物                                 |
| `npm run typecheck-client` | 仅类型检查(`tsc -p ./src/tsconfig.json --noEmit --skipLibCheck`)        | 只验证改动不产物(本 fork 定制改动的快速自检) |

> [!warning] 裸 tsc 的噪音
> 直接 `tsc -p src/tsconfig.json` 会报大量 `Cannot find module 'electron'` / `Cannot find namespace 'Electron'` 之类**环境噪音**(正式构建走 gulp,不是裸 tsc)。自检时用 `npm run typecheck-client`,或只确认报错里**不含**你改的文件名。

> [!note] watch 首次较慢
> `npm run watch` 首次全量编译要几分钟,等它输出 "Finished compilation" 再启动开发版。常驻后改动秒级增量。

## 4. VS Code fork · 启动开发版

**在 VS Code fork 根目录跑**:

```powershell
cd d:\soft\Kiro_back\My-Agent-editor\vscode

$env:vs2022_install = "H:\soft\install\vsbuild"
Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process
npm install

# 基本启动(Windows)
.\scripts\code.bat
# mac/linux 对应 ./scripts/code.sh


npm run watch

# 启动并加载 Continue 扩展(开发调试推荐)
.\scripts\code.bat --extensionDevelopmentPath="d:\soft\Kiro_back\My-Agent-editor\continue\extensions\vscode"

#生产打包

# 1. 解包内置扩展(含 Continue)
npm run download-builtin-extensions
# 2. 生产编译
npm run compile-build
npm run compile-extensions-build
# 3. 打发行版(具体平台任务名需确认)
npm run gulp vscode-win32-x64-min   # 或对应的 gulp 发行任务
```

> [!info] scripts/ 下的其它启动脚本(按需)
>
> - `code.bat` / `code.sh` —— 桌面(Electron)开发版,最常用
> - `code-web.bat` / `code-web.js` —— 浏览器里的 web 版
> - `code-server.bat` —— server 版
> - `code-cli.bat` —— CLI
>   先 `npm run watch`(或 `compile`)有产物,`code.bat` 才能跑起来。

## 5. VS Code fork · 发行级打包(需要分发时才用)

通过 `npm run gulp <task>` 调 gulp 任务(`gulp` 脚本已带 `--max-old-space-size=8192`):

| 命令                                  | 作用                                                  |
| ------------------------------------- | ----------------------------------------------------- |
| `npm run compile-build`               | 带 mangling 的生产编译(`compile-build-with-mangling`) |
| `npm run minify-vscode`               | 压缩 vscode 产物                                      |
| `npm run compile-extensions-build`    | 构建内置扩展(生产)                                    |
| `npm run gulp vscode-win32-x64`(示例) | 产出平台发行包(具体任务名见 `build/gulpfile*.js`)     |

> [!tip] 日常验证不需要发行打包
> 验证本 fork 的定制改动,`watch` + `code.bat` 就够。§5 仅在要产出可分发的安装包时用。

## 7. 选择决策表(改了什么 → 跑什么)

| 改动范围                                | Continue 侧                                                                  | VS Code fork 侧                           |
| --------------------------------------- | ---------------------------------------------------------------------------- | ----------------------------------------- |
| 只改扩展 `package.json`(如本次容器位置) | 若 `out/` 已有产物,**无需重编**;否则至少 `install-dependencies.ps1` 跑过一次 | —                                         |

| 改 `core` / 依赖变动                    | `.\scripts\install-dependencies.ps1`(整体)                                   | —                                         |
| 改 `src/vs/**`(workbench)               | —                                                                            | `npm run watch` / `compile`,再 `code.bat` |
| 要分发安装包                            | 扩展 `npm run package`(vsix)                                                 | §5 gulp 发行任务                          |
